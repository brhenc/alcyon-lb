# Alcyon Struct Size & Layout Map (2026-11-19)

Measurement of per-connection, per-stream, per-request, and per-proxy/per-server structs on `b5fef2d2` (`agy/integration-1119`), `x86_64-unknown-linux-gnu`.

## Method

- `rustup` / a nightly Rust toolchain is not installed on this host (system `rustc 1.99.1 (58cf8f9c3 2026-10-13) (Fedora 1.99.1-2.fc45)`), so `RUSTFLAGS=-Zprint-type-sizes` could not be used.
- Instead, a test-only helper in [`crates/alcyon-rt/tests/it/size_map.rs`](file:///var/tmp/qwen-next-eval/gemini-sizemap/crates/alcyon-rt/tests/it/size_map.rs) (`#[ignore = "prints a report; run by hand"]`) uses `core::mem::offset_of!`, `core::mem::size_of`, and `std::any::type_name` to print exact field offsets, sizes, and padding.
- No changes were made under `crates/*/src`. For the few private fields that cannot be named by `offset_of!` from an integration test (`TcpSession::cli`, `H2MuxContext::{lower_name, decoded, block_scratch, head_wait}`, `StreamLog::date_cache`, `ServerArrays`, `Cell`), their exact sizes were measured via their public types (`ClientSide`, `DecodedFields`, `RateCtr`, `ServerAddrs`, etc.) and cross-checked against the exact offset gaps left by the surrounding `pub` fields.
- Each table below is **sorted by `size` descending** (ties broken by `offset` ascending). `padding after` is computed in memory-offset order (`next_field_offset - (offset + size)`, or `struct_size - (offset + size)` for the last field in layout order).

## Summary & Answers

1. **How many bytes are `bool` fields?**
   - **`SessionEntry` total (including inline `TcpSession`, `Stream`, `StreamLog`, `HttpTxn`)**: **63 bytes** of `bool` (plus 1 byte `Option<bool>`):
     - `SessionEntry` (direct): **6 bytes** (6 fields)
     - `TcpSession`: **36 bytes** (36 `bool` fields; plus 1 byte `req_head_deferred: Option<bool>`)
     - `StreamLog` (inline in `TcpSession::strm`): **4 bytes** (4 fields)
     - `HttpTxn` (inline in `TcpSession::strm::txn`): **17 bytes** (17 fields)
   - Other measured structs: `H2Child` **3 bytes**, `H2StreamCtx` **5 bytes**, `H2MuxContext` **6 bytes**, `Proxy` **9 bytes**.

2. **How many bytes are `Option<Tick>` / `Option<u32>` / `Option<Instant>` that a sentinel or niche could halve?**
   - **`Option<Tick>` / `Option<u32>` / `Option<Option<u32>>` (8 bytes → 4 bytes with sentinel/`NonZeroU32`)**:
     - `TcpSession`: **32 bytes** across 4 fields (`so_id: Option<u32>`, `inspect_exp: Option<Tick>`, `res_inspect_exp: Option<Tick>`, `res_inspect_armed: Option<Option<u32>>`) → **16 bytes** saved.
     - `StreamLog`: **8 bytes** (`last_rule: Option<u32>`) → **4 bytes** saved.
     - `H2MuxContext`: **8 bytes** (`continuation_stream: Option<u32>`) → **4 bytes** saved (stream IDs are 31-bit non-zero).
     - Total in `SessionEntry`: **40 bytes** (5 fields), **20 bytes** saveable.
   - **`Option<Instant>` (16 bytes each; uses `Instant`'s nanosecond niche, so `Option<Instant>` == `Instant` == 16 bytes)**:
     - `StreamLog`: **80 bytes** across 5 fields (`first_byte`, `request`, `queue`, `connect`, `data`), plus `start: Instant` (16 bytes). Storing `u32` millisecond offsets (or `Option<NonZeroU32>` deltas) relative to `start` would shrink 80 bytes → 20 bytes (**60 bytes** saved; or 40 bytes if `u64`).

3. **How many bytes are `usize` indexes that could be `u32` / `u16`?**
   - **`SessionEntry` (direct)**: **40 bytes** across 4 fields:
     - `target_server_idx: Option<usize>` (**16 bytes** → `Option<u32>` with sentinel `u32::MAX` or `NonZeroU32` is **4 bytes**, saving **12 bytes**)
     - `proxy_idx: usize` (**8 bytes** → `u32`/`u16`, saving **4–6 bytes**)
     - `backend_idx: usize` (**8 bytes** → `u32`, saving **4 bytes**)
     - `srv_backend_idx: usize` (**8 bytes** → `u32`, saving **4 bytes**)
     - Total saved with `u32`: **24 bytes** (40 → 16 bytes).
   - **`TcpSession`**: **32 bytes** of `usize` buffer/config sizes (`htx_tail`, `htx_blocks`, `bufsize`, `maxrewrite` — all bounded well below 4 GiB → `u32` saves **16 bytes**). (Note: `tracked_sc: [Option<(usize, StickKey)>; 3]` also holds `usize` table indexes, though `StickKey` dominates its 40-byte slot.)
   - **`H2StreamCtx`**: **32 bytes** (`rx_buffered`, `rx_fill`, `rx_limit`, `abs_len` → `u32` saves **16 bytes**).

4. **Which inline sub-structs are larger than 64 bytes and are rarely used (candidates for a cold box)?**
   - `TcpSession::tracked_sc: [Option<(usize, StickKey)>; 3]` (**120 bytes**) — unused on connections without `track-sc*`. Cold-boxing (`Option<Box<...>>`, 8 bytes) saves **112 bytes** per connection.
   - `HttpTxn::{body_wait, req_body, rsp_wait}` (**64 bytes** combined: `16 + 24 + 24`) — only used by `wait-for-body`. Cold-boxing together saves **56 bytes** per `HttpTxn`.
   - `H2Child::rsp_head: Option<RspHead>` (**400 bytes**) — inline in `H2Child` (648 bytes). Boxing (`Option<Box<RspHead>>`, 8 bytes) saves **392 bytes** per `H2Child` when unset.
   - `H2MuxContext::decoded: DecodedFields` (**72 bytes**) — scratch buffer used only while decoding an HPACK header block.
   - `Proxy::stats_config: StatsConfig` (**328 bytes**) — only used on proxies with `stats enable`. Cold-boxing saves **320 bytes** per backend (19.2 MB across 60,000 backends).
   - `Proxy::cookie: Option<CookieConfig>` (**96 bytes**) — only used on backends with cookie persistence. Cold-boxing saves **88 bytes** per backend.
   - `Proxy::{error_files, error_replies}` (**48 + 48 = 96 bytes**) — two inline `HashMap`s, empty on most proxies.

5. **Five biggest wins in bytes for `SessionEntry` (currently 1,672 bytes):**
   1. **Cold-box `TcpSession::tracked_sc` (`[Option<(usize, StickKey)>; 3]`, 120B → 8B)**: **−112 bytes**
   2. **Replace `StreamLog`'s 5 `Option<Instant>` fields (80B) with `u32` ms-deltas from `start` (20B)**: **−60 bytes**
   3. **Cold-box `HttpTxn`'s `wait-for-body` state (`body_wait` + `req_body` + `rsp_wait`, 64B → 8B)**: **−56 bytes**
   4. **Pack `bool` flags into bitfields (63 bytes across `SessionEntry`/`TcpSession`/`StreamLog`/`HttpTxn` → ~8–12B)**: **−51 to −55 bytes**
   5. **Shrink `SessionEntry` index fields (`target_server_idx: Option<usize>` 16B → 4B, `proxy_idx`/`backend_idx`/`srv_backend_idx` 24B → 12B)**: **−24 bytes**
   *(Next in line: deduplicating/compacting `TcpSession`'s 6 × 32B `Option<SocketAddr>` fields = **−32 to −64 bytes**, and sentinelizing `Option<Tick>`/`Option<u32>` = **−20 bytes**.)*
