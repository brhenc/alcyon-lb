## 0. Short answers

| Question | Answer |
|---|---|
| Is `crates/ibex-dns` useless? | **No.** Its shape is right: sans-IO (`query` / `poll_transmit` / `handle_response` / `poll_timeout` / `poll_result`), no threads, no sockets, `forbid(unsafe_code)`, and its decoder (`hickory-proto`) survived 300,000 hostile replies without a panic in 0.4 s (B.P11) and refuses the compression-pointer loop (its own tests). | What is wrong with it? | Its **policy** is a guess, not a port, and three of the guesses are security-relevant: message IDs are 1, 2, 3 (B.P1) where HAProxy's are random (A.t3: 15353, 18250, 23956...); a reply is matched by ID only, so a reply for another name from any address is accepted (B.P2); and `accepted_payload_size` is stored and never sent (B.P7). | What does an operator get, and when? | T483: hostnames on `server` lines (libc at start, `init-addr`), which Ibex refuses today ("invalid IP address", A.t0). T484: `resolvers` + run-time A/AAAA resolution, address swaps, `hold`, logs, `show servers state`. T485: `show resolvers`. T486: `server-template` with A/AAAA. T487: SRV. T488: TCP fallback, `tcp@`, EDNS sizes. T489: `do-resolve`, `set server fqdn`, `parse-resolv-conf`, `dns-accept-family`. |

## Part 1. What HAProxy does, measured

Facts, each with its appendix row. F1-F8 shape the design most.

- **F1 Start-up is libc, run time is the resolver.** A hostname on a `server` line is resolved by
  `getaddrinfo` while the configuration loads (`init-addr` default `last,libc`, plus `none` when
  `resolvers` is set, `server.c:5602-5625`). Without `resolvers`, an unresolvable name is fatal
  (A.t0: `could not resolve address 'nosuch.invalid'`, `Failed to initialize server(s) addr`); with
  `resolvers`, the server starts in `MAINT (resolution)` and the first answer brings it up
  (A.t1a: `could not resolve address 'a1.test', disabling server` then at 0.4 s `IP changed from
  '(none)' to '10.0.0.1' by 'r/ns1'`, `administratively READY thanks to valid DNS answer`).
  `init-addr <ip>` starts with that address and the resolver replaces it (A.t1c); `init-addr libc`
  alone is fatal when libc fails (A.t1d); `init-addr last,libc,none` without `resolvers` starts the
  server in RMAINT and nothing ever brings it up (A.t1e). libc prefers IPv6: `localhost` becomes `::1`
  (A.t1f). Ibex today refuses every hostname but `localhost` (A.t0, `address.rs:185`).
- **F2 One query every `timeout resolve`, TTL ignored.** A.t2: TTL 300, `timeout resolve 2s`: queries
  at 0, 2, 4, 6 s. A.t1a: default 1 s. Every nameserver gets every try at the same instant (T477,
  A.t10: ns1 and ns2 at 296.48 and 297.78).
- **F3 An address change is applied at the next answer, logged, and live connections are untouched.**
  A.t3: zone changed at 2.13, the 2.72 answer carries it, `l/s1: IP changed from '10.0.0.1' to
  '10.0.0.2' by 'r/ns1'` (a WARNING on stderr and a log line); `show servers state` shows the new
  address at 3.17. A.t3b: a client keep-alive connection in flight keeps working; its next request
  after the change goes to the new address (requests 1-4 answered by `127.0.0.1`, 5-10 by
  `127.0.0.2`, same client socket), i.e. the idle server connection to the old address is not reused
  (the idle pool is keyed by the address: Ibex's `IdleKey.addr`, engine.rs:86, is already).
- **F4 Errors are retried before they count, then the hold decides.** On NX/REFUSED/SERVFAIL/NODATA/
  silence HAProxy resends the same query id every `timeout retry`, `resolve_retries` times, and only
  then sets the status (A.t4: NX from 2.6, re-sent at 3.6 and 4.6 with id 52136, status at ~5.6).
  Then `snr_set_srv_down`: if `last_valid + hold <status>` has expired the server goes
  `MAINT`, else nothing changes and the old address stays (`server.c:5135-5195`). With `hold nx 3s`
  and the last valid answer at 1.6, DOWN at 5.6 (A.t4: `going DOWN for maintenance (DNS NX
  status)`); `hold timeout 3s` → `(DNS timeout status)` at 5.6 (A.t5); `hold refused 2s` →
  `(DNS refused status)` (A.t6); SERVFAIL and NODATA → `(unspecified DNS error)` under `hold other`
  (A.t6b, A.t6c; counters `other` resp. `any_err`). A valid answer brings the server back at once
  (`administratively READY thanks to valid DNS answer`, A.t1a). After an error the next resolution
  waits `timeout resolve` from the report, not from the first send (A.t4: 7.6).
- **F5 A nameserver that never answers = timeout; a closed port too.** A.t7: `nameserver dead
  127.0.0.1:15399` (ICMP unreachable), `snd_error 0`, `sent 6`, DOWN at 3.2 s with `(DNS timeout
  status)`; the `init-addr 10.9.9.9` address served until then. A name that was never valid is
  taken down at its first error status (A.t7, A.t4b).
- **F6 Families.** `dns-accept-family` defaults to `auto` = IPv4, plus IPv6 only if the host has an
  IPv6 route (`is_inet6_reachable`, a UDP `connect()` cached 30 s). On this host (no v6 default
  route) only `A` is ever sent, and a v6-only name stays in MAINT (A.t8, A.t18: `both.test` gets
  `10.0.0.1`). With `dns-accept-family ipv4,ipv6`: `resolve-prefer` picks the query type (default
  ipv6: only AAAA sent, A.t18b); an error on the preferred type is retried **immediately** with the
  other type, same id, without using a try (A.t8b: `A` NODATA then `AAAA` in the same millisecond,
  address `2001:db8::6`; A.t8c: NX on both, three pairs).
- **F7 Selection among several addresses.** `resolv_get_ip_from_response` scores each record: +8
  preferred family, +4 `resolve-net` match (A.t19: `10.0.0.2/32` chosen out of three), +2 not used by
  another server of the backend with the same name, +1 the current address (so a server keeps its
  address while it is still in the answer). Two servers on one name with one address: the second has
  no IP and is MAINT (A.t12b, `No IP for server`); `resolve-opts allow-dup-ip` shares it (A.t12c).
- **F8 Validation and counters.** Question count 1, name, class, type checked; `ancount` capped by
  the payload; a reply longer than `accepted_payload_size` is `too_big`; an unknown id is `outdated`
  (`resolvers.c:2373-2470`). `show resolvers` prints per nameserver `sent, snd_error, valid, update,
  cname, cname_error, any_err, nx, timeout, refused, other, invalid, too_big, truncated,
  tcp_fallback, outdated` (A.t5), the same 16 names as the `haproxy_resolver_*` Prometheus metrics
  (`resolvers.c:46-63`; the reference binary is built without the exporter, A.t13).
- **F9 TC → TCP.** A truncated UDP answer is retried over TCP to the same nameserver, immediately,
  without consuming a try; TCP queries are numbered 1, 2, 3 per stream (A.t9, counters `truncated 3,
  tcp_fallback 3`). `nameserver tcp@...` sends everything over TCP (A.t15c). A truncated TCP answer
  is an error.
- **F10 EDNS.** Every query carries an OPT record announcing `accepted_payload_size` (A.t1a:
  `edns=512`; A.t15: `edns=4096`). The query is 24 + name bytes with it; the crate sends 24 without
  (B.P7).
- **F11 `server-template` with A records.** N slots share one resolution; each takes a distinct
  address (`by 'r/ns1'` for the first, `by 'DNS cache'` for the others, A.t12); a slot whose address
  leaves the answer goes `MAINT (No IP for server)` at the next answer, no hold (A.t12: 10.0.0.2
  dropped at 1.77, srv2 MAINT at 2.77).
- **F12 SRV.** A name starting with `_` is an SRV query. Each record fills a slot: target FQDN
  (`changed its FQDN from (null) to t1.test by 'SRV record'`), port (`port changed from '+0' to
  '8080'`), address from the additional record (`by 'DNS additional record'`) or, without one, a
  separate A resolution per target (A.t11b: `A t1.test`, `A t2.test` after the SRV answer); weight
  `(w + 255) / 256` (A.t11: 512 → 2, 256 → 1). A record missing from the answer for `hold obsolete` is
  removed and its slot goes `MAINT (entry removed from SRV record)` (A.t11: removed at 1.69, `hold
  obsolete 2s`, MAINT between 2.69 and 3.72).
- **F13 `do-resolve`.** `http-request do-resolve(txn.ip,r,ipv4) str(a1.test)` resolves once and
  serves the next request from the cache inside `hold valid` (A.t14: one query for two requests
  2.3 s apart; `sent 1, valid 1`).
- **F14 Run time.** `set server l/s1 fqdn both.test` switches the name and the next query (A.t21).
  A health check that ends in an L4 timeout asks for a resolution, but only when the last one is
  older than `hold valid` (`resolv_trigger_resolution`, `resolvers.c:570-600`); with `timeout
  resolve 10s` and two failed checks in 6 s no extra query appeared (A.t16).
- **F15 Threads.** One task per `resolvers` section, pinned to one thread, the sections spread
  round-robin (`resolvers.c:2866-2878`: "make sure that the same thread deals with DNS I/O and
  scheduling"); one connected UDP socket per nameserver (`dns.c:62-130`), so the kernel chooses a
  random source port and filters the source address. Server updates take `SERVER_LOCK`; the
  resolvers' state is under `DNS_LOCK` (`resolvers.c:2383`).
- **F16 Config errors.** `hold nx foo` → `unexpected character 'f' in argument to <hold>`, fatal
  (A.t15d). `parse-resolv-conf` adds the system nameservers in order (A.t15b: `127.0.0.53` then
  `ns1`). A `default` section with `parse-resolv-conf` is created when none is declared (A.t5:
  `Resolvers section default`, used by the httpclient only).

## Part 2. The design

### 2.1 Placement: one owner worker per section, nothing shared on the request path

A `Resolvers` object per `resolvers` section lives in the engine like the checks do: a
`Kind::Resolver` task (`ibex-sched` `Kind`, after `Listener`) created at `init_checks` time on the
worker that owns the section (sections round-robin over workers, F15), one `DgramSocket` per
nameserver `connect()`ed to it (`dgram.rs`; the kernel picks the source port, the connection filters
the source address, as `dns.c:106`), registered in `fdtab` as `FdState::Resolver { section: u32 }`
(a new variant beside `QuicListener`/`Mailbox`). Readiness and timers drive the sans-IO
`ibex_dns::Resolver` exactly as `step_check` drives a check: the task runs, calls `handle_response`
for every datagram read, `poll_transmit` until empty, `poll_result`, and re-arms its timer at
`poll_timeout()` min the next `timeout resolve`.

Nothing is read by another thread except through two shared cells that already exist:

- the address: `Proxy::servers: ServerAddrs` (`srv_rt.rs:267`, a seqlock per server that
  `set server ... addr` writes today, `applet.rs:1779`); the owner worker calls `servers.set(idx,
  addr)` and every worker's next connection goes there. The request path's read is unchanged.
- the admin state: `Proxy::server_statuses: Arc<Vec<AtomicU8>>` with `ServerStatus::Maint`, and
  the check's `set_admin_status`, as `disabled`/`set server state maint` use (engine.rs:4357).

Health checks must read `proxy.servers.at(idx)` at each run instead of the `check.addr` fixed at
construction (`check.rs:1672`, `:1763`): today `set server addr` moves the traffic and not the check
(a latent gap T484 closes, with a test that fails first).

### 2.2 Objects

```
Resolvers (one per section, owned by a worker)
  cfg: ResolverConfig                      (the 11 knobs)
  nameservers: Vec<Nameserver { addr, sock: DgramSocket, counters: ResolverCounters }>
  resolver: ibex_dns::Resolver             (ids, in-flight, transmits)
  resolutions: Pool-backed Vec<Resolution> (one per distinct (name, family) among the requesters)
  by_query: map QueryId -> resolution index
Resolution
  name: Box<str> (interned at config), kind: A|Aaaa|Srv, prefer: family
  status: None|Valid|Nx|Refused|Timeout|Other|Invalid, last_valid: Tick, last_resolution: Tick
  answers: [AnswerItem; <= max_answer_records] with last_seen per item (F12's obsolete rule)
  requesters: Vec<(proxy_idx, server_idx)>
```

A server with `resolvers` is a requester of one resolution; `server-template` slots on one name
share it (F11); an SRV slot's target is a requester of its own A/AAAA resolution (F12). `Resolution`
and `AnswerItem` come from an `ibex_alloc::Pool` registered like `check::register_pools`
(`docs/design/memory-2026-10-24.md` §3); their counts are bounded by the configuration (requesters)
and by `max_answer_records = (accepted_payload_size − 12) / 6` per resolution, so the resolver's
memory is a config-time number, shown in `show pools`.

### 2.3 Timers and the state machine (per resolution), as measured

1. Every `timeout resolve` from the last report: send (all nameservers, F2) with a fresh random id.
2. No valid answer: resend the same id every `timeout retry`, `resolve_retries` − 1 more times; an
   error on the preferred type with both families accepted is retried at once with the other type
   (F6). After the last try with no valid answer: status from the last error, or `Timeout` if none.
3. A valid answer: `last_valid = now`, pick the address per F7's score, publish if changed (log
   `<px>/<srv>: IP changed from 'a' to 'b' by '<section>/<ns>'`), bring the server out of RMAINT.
4. An error status: if `last_valid + hold <status>` has expired (or the name was never valid, F5)
   → `Maint`, log `Server <px>/<srv> is going DOWN for maintenance (<reason>)`, clear the address
   in `show servers state` (`-`), counters.
5. Next resolution at `last_report + timeout resolve`.

The `hold` values are read at step 4 only; `hold valid` is read by `do-resolve` only (T489);
`hold obsolete` by SRV only (T487).

### 2.4 Hostile input

- A reply is accepted only from a connected socket (kernel-filtered source), with a 16-bit random id
  taken from `ibex_rt`'s existing RNG, the question name compared byte for byte, type and class
  checked, `ancount` capped (F8). What fails is counted (`invalid`, `outdated`, `too_big`) and
  dropped; nothing an attacker sends can change a server's state without guessing id and source port
  in the `timeout retry` window, the same bar as HAProxy.
- The decoder is hickory's (compression loops and short buffers refused: the four hostile tests;
  B.P11). The crate's answer vector is capped at `max_answer_records` before it is built.
- Reads use one 64 KiB buffer owned by the task (no allocation per datagram); replies over
  `accepted_payload_size` are dropped before decoding.
- `-dr`-like leniency is not added: an invalid name on a server line is a config error (B.P9).

### 2.5 Logging, CLI, stats

Logs and `show servers state` / `show stat` strings are HAProxy's byte for byte (A.t1a, A.t3, A.t4,
A.t11): the `srv_admin_state` bits (0x20 RMAINT), `MAINT (resolution)` in `show stat`, `-` for a
server without an address, `srv_fqdn`, `srv_port`, `srvrecord`. `show resolvers` is F8's 16 counters
per nameserver plus the auto-created `default` section (F16) once `parse-resolv-conf` exists; the
Prometheus names are `haproxy_resolver_<counter>{resolver, nameserver}`.

### 2.6 Memory and the request path

- Request path: unchanged. Budget per slice: `tools/measure/insreq.sh` keep-alive scenario before
  and after, within ±0.5%; the number goes in the task's report (AGENTS.md §8).
- Resolver path (one worker, once per `timeout resolve` per name): no `String` per query; names
  are `Box<str>` interned at config; the query buffer is reused; answers go into pooled
  `AnswerItem`s. The `do-resolve` cache (T489) is a `Pool`-backed map keyed by the interned name
  with `hold valid` expiry, bounded by a config knob (`tune.resolvers.cache-size`, Ibex-only,
  default 1024 entries) because its keys come from requests.

### 2.8 Open questions for the user

1. **`hickory-proto`'s 79-crate tree.** Keep (this design) or replace with a hand-written RFC 1035
   codec (~400 lines + the same hostile tests, one task, S) before T484 wires it in. The scan list
   reports no `unsafe` in the tree; the cost is build time and audit surface.
2. **`dns-accept-family` default.** HAProxy's `auto` probes an IPv6 route every 30 s. Until T489,
   Ibex accepts both families (A/AAAA fallback as F6) — on a host without IPv6 that can select an
   unreachable AAAA where HAProxy would not. Alternative: default to `ipv4` until T489.
3. **`init-addr last`.** Ibex has no server-state file; `last` is accepted and skipped (as HAProxy
   does without a file). Say so in differences.md, or refuse it?
4. **The `default` resolvers section** (F16) exists in HAProxy for the httpclient. Not built; `show
   resolvers` will differ by that block. Acceptable?
