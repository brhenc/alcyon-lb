# Design: Ibex's memory management, one abstraction (2026-10-24)

Status: design, no production code. Supersedes the slice plan of `pools-2026-10-18.md` §5 and
T372; keeps that document's HAProxy spec (§1-§3) as the reference. Numbers below are from
today's runs (§1, scripts in `tools/measure/insreq.sh` and `insprof.sh`; raw output in §9).

## 0. Short answers

| Question | Answer |
|---|---|
| Is Ibex's memory management "extremely expensive"? | On the **plain keep-alive path, no**: 36.8k instructions per request against HAProxy's 33.3k (+10%), of which the pools, spares and wipe are ~1.4k (5.5% of Ibex's own instructions) against HAProxy's ~2.3k of pool and malloc work. On the **rules path, the cost is real but it is not where the gap is**: Ibex 76.7k against HAProxy 42.0k; its spare strings, header lists and pools cost ~5.3k per request (HAProxy's pools and malloc: ~4.2k). The other ~30k of the gap is the rule engine rebuilding and re-parsing the request after every header action, cloning a 300-byte sample context per rule, hashing expression text at run time, and re-validating UTF-8 (§1.3). Those are instructions for no reason too, and §6 slice S7 removes them, but they are not allocations. |
| What went wrong? | The 2026-10-18 design (`Pool<T>`, one per-thread budget, P0) was never built. Seven hand-written per-thread caches were built instead, each with its own limit, counters and drain (§2.1). fix/t444 then added HAProxy's budget to *one* of them with per-operation shared-counter stores and cost +3.6k instructions per request (+4.7%) for ~130 take/give operations: ~28 instructions of accounting per operation, as much again as the operation itself. |
| The design | One type, `ibex_alloc::Pool<T>`, for every per-thread cache (§3): per-thread LIFO cache, **one** per-thread byte budget (`tune.memory.hot-size`, HAProxy's 3/4 and 7/8 rule), **thread-local** counters published to `show pools` once per loop pass (never a shared cache line on take or give), one wipe policy, one `pool_gc` walk, one fallible `take`. Budget per operation: take ≤ 50 instructions, give ≤ 60, accounting ≤ 10 of those (§4). HAProxy's hit path is 46 (`__pool_alloc`) and ~60 (`__pool_free` + `pool_put_to_cache`). |
| Shared tier? | No (§3.6). HAProxy ships with the global pool **off** (`no-global`); eviction frees to libc. Ibex's threads do not hand pooled objects to each other on the request path; where an object does cross (an idle server connection taken over by another worker), the receiving thread's cache takes it and the global `allocated` counter is untouched. |
| Verdicts (§5) | fix/t444: **do not merge the implementation; take its tests, parser and wipe into S1.** fix/t445: **merge**; S3 replaces its hand-written drain list with the registry walk. T448: **rewritten** as S5+S6. T458: **superseded** by S1 (the budget *is* its checklist). T453: **keep**, merge as is. |

1. **Memory management proper is ~5.3k of Ibex's 76.7k** (spares 4.1k, buffers 0.3k, idle
   pool 0.6k, no malloc at all). HAProxy spends 4.2k. Per operation the two are close; Ibex does
   ~130 spare operations per request where HAProxy does ~26 pool operations, because Ibex's
   rules materialise header values and samples as `String`s and HAProxy writes into the HTX.
2. **HAProxy is not malloc-free at 50 connections per thread.** `pool_evict_last_items` and

   plain scenario, are its 512 KiB hot cache evicting 16 KiB buffers (24 buffers at the 3/4
   mark) and taking them from libc again. Ibex's 64-buffers-per-thread cache is at 0. This
   matters for Q1 and for how the byte budget treats buffers (§3.3).

### 1.4 What fix/t444 pays for (`spare.rs` on the branch)

Per take and per give: `LocalKey::try_with` + `RefCell::borrow_mut` (shared with main), a
relaxed load of the global `EPOCH`, a relaxed load of the global `HOT_SIZE` (give), **four
relaxed stores into an `Arc<Shown>`** that the CLI thread reads, a `bytes() + cap <= hot_size()`
compute, and `ibex_alloc::wiped` (wipe, `clear`, `from_utf8` on an empty `Vec`) even with
zero-buffers off. ~28 instructions over ~130 operations = the measured +3.6k. The stores go to
a cache line another thread reads whenever `show pools` runs: the one thing the fast path must
never do. HAProxy's `pool_put_to_cache` hit path: two list inserts, `ph->count++`,
`pool_cache_count++`, `pool_cache_bytes += size` (all thread-local), one compare against
`pool_cache_size * 3/4`. Its `used`/`allocated` atomics move only on a cache miss
(`pool_alloc_nocache`) and on a free to the OS (`pool_free_nocache`).

## 3. The design: `ibex_alloc::Pool<T>`

### 3.1 Types

```rust
/// What a pooled object must do. Safe Rust; no Drop magic beyond `PoolBox`.
pub trait Poolable: 'static {
    /// Bytes this object holds (its capacity, not its length): the byte budget sums these.
    fn footprint(&self) -> usize;
    /// Make it ready for the next owner: clear it, and wipe the used bytes when `wipe`.
    fn reset(&mut self, wipe: bool);
    /// Not worth keeping (too small to matter, too large for `tune.memory.hot-size`): freed.
    fn keep(&self, max_footprint: usize) -> bool { self.footprint() <= max_footprint }
}

pub struct Pool<T: Poolable> {
    spec: PoolSpec,                        // name, file, line, nominal size, class
    allocated: AtomicUsize,                // objects obtained from the OS (miss path only)
    failures: AtomicUsize,                 // refused takes (miss path only)
    limit: AtomicUsize,                    // 0 = none; buffers: tune.buffers.limit
    shown: [ShownCounters; MAX_THREADS],   // per-thread snapshot the CLI reads, written by the owning thread once per pass
    cache: LocalKey<RefCell<LocalCache<T>>>, // the thread_local! the macro declares
}
struct LocalCache<T> { items: Vec<T>, count: usize, bytes: usize, dirty: bool, floor: usize }

/// An owned object that goes back to its pool on drop. Deref<Target = T>.
pub struct PoolBox<T: Poolable> { v: Option<T>, pool: &'static Pool<T> }

declare_pool!(pub static SPARE_STR: Pool<String>, "spare_str");   // thread_local! + registry entry
```

API: `take() -> Option<PoolBox<T>>` (cache, else fallible growth, else `None`;
`failures += 1` on `None`), `take_with(init)`, `give(T)` (what `PoolBox::drop` calls),
`prefill(n)` at start, `drain_local() -> usize` (this thread, for `pool_gc`), `publish()`
(this thread, once per loop pass, only when `dirty`). `Buf` keeps its API and becomes the
`PoolBox<Box<[u8]>>` user it already almost is; `Vec<(String, String)>` lists, `Vec<u8>` lines
and captures, `Vec<Slot>` variable stores, `Box<CheckRun>` and `Vec<String>` stats rows are
`Poolable` with ten-line impls. The arenas (§3.7) implement a sibling trait, `Arena<T>`, that
registers with the same budget and registry but hands out indices.

### 3.2 Take and give, the fast path

```
take:  cache.try_with(|c| c.borrow_mut().items.pop())    // TLS + RefCell: ~12 instructions
       Some(v) => c.count -= 1; c.bytes -= v.footprint(); c.dirty = true; PoolBox   // ~8
       None    => grow() (miss path: try_reserve, allocated.fetch_add, maybe failures)
give:  v.reset(wipe)                      // clear + wipe of the *used* length when zero-buffers is on
       if !v.keep(hot.max_item) || c.count >= c.hard_count { drop(v); return }   // ~6
       c.items.push(v); c.count += 1; c.bytes += fp; c.dirty = true;              // ~10
       HOT.bytes += fp;                   // thread-local total across pools, a Cell          // ~3
       if HOT.bytes > HOT.three_quarters { evict(c) }                                       // ~3 (compare)
```

`HOT` is one `thread_local!` in ibex-alloc: `{ bytes, count, max, three_quarters, seven_eighths,
max_item, wipe }`, filled from the config when the thread starts (so no global load per
operation: fix/t444's `hot_size()` and T458's complaint). `wipe` is the thread's copy of
`tune.ibex.zero-buffers`; `set_zero_buffers` bumps a generation the loop checks once per pass.
No branch on the fast path reads a global.

### 3.3 One budget, one eviction rule

- `tune.memory.hot-size <bytes>` (HAProxy's parse: `too_many_args(1)`, `atol`, "expects a
  strictly positive value", default 524288; fix/t444's parser and `hot_size.rs` test are
  correct and are kept). It bounds the **sum of footprints of every pooled object cached by
  one thread**, across all pools, as `pool_cache_bytes` does.
- Give: when the thread's total passes 3/4 of the budget, evict from the pool being given to
  until it holds ≤ 16 + count/8 objects or the total is ≤ 3/4 (HAProxy's
  `pool_evict_from_local_cache`); when the total passes the budget, evict largest-first across
  the thread's pools until ≤ 7/8 (`pool_evict_from_local_caches`, with the deviation of §2.3).
  Evicted objects are dropped: `allocated -= 1` (one atomic per evicted object, cold path).
- **Floor.** Each pool declares a per-thread floor that eviction never goes under (HAProxy's
  `minavail`, 2 for buffers; emergency buffers are outside the pool). The buffer floor is where
  §1.3's second finding lands: with 50 keep-alive connections and 16 KiB buffers, a 512 KiB
  budget means HAProxy mallocs ~0.5 buffer per request. Ibex sets the **standard buffer floor
  to 64 per thread** (today's count limit, measured at 0 malloc) and counts floor objects
  against the budget only above the floor. Documented as an Ibex extension in `tradeoff.md`:
  Ibex at the HAProxy default is malloc-free where HAProxy is not. `tune.buffers.limit`
  (default 0 = none) and `tune.buffers.reserve` (default 4) parse as HAProxy parses them (S5).
- Only `pool_gc` (§3.4) goes below the floor.

### 3.4 One `pool_gc`

fix/t445's shape is right: a global generation, `pool_gc::poll()` once per loop pass (one
`Acquire` load and a `Cell` compare), each thread drains its own caches, then `trim_heap()`.
What changes: `drain_thread_caches()` stops enumerating seven modules and walks the
**registry** (every `declare_pool!` registers a `drain_local` fn pointer, every arena a
`compact` fn pointer); the arenas' `trim_tail` compaction moves here (§3.7). Triggers stay
T445's: SIGQUIT, SIGTTOU (pause), SIGUSR1 (soft stop), the stop path after stick tables, a
refused allocation (S5: `take()` returning `None` requests a GC and retries once, as
`ssl_sock.c:6074` does). Wipe on drain when zero-buffers is on (already).

### 3.5 One place a failed allocation is seen

`Pool::take` is the only growth point: `grow()` uses `try_reserve_exact` (bytes, `Vec<T>`) or the
one-element `Vec` trick (boxes). On `Err`: `failures += 1`, `pool_gc::request()`, retry once,
then `None`. Callers see `None` and decide per object as HAProxy does (`pools-2026-10-18.md`
§2.3, §4.4): a session slot or TLS context → refuse the connection (static 500 on HTTP
listeners, termination `R`); a stream object → fail that stream; a **buffer → M1: fail the
stream (plan-2100 Z4); after the Q3 measurement: queue (S6)**. Infallible allocations in
rustls, h2, std and the config path stay as `tradeoff.md` 6.23 records them; `-m` does not set
`RLIMIT_DATA` before S5 lands (T453 §2). `tune.fail-alloc` / `-dMfail` become implementable in
`grow()` (10-18 spec §4.6) in S5.

### 3.6 Shared tier: none

HAProxy's global pool is off by default since 2.x (`-dMhelp`: `no-global`); evicted objects go
to `free()`; its "0 malloc" is a per-thread property. Ibex's workers are even more
independent: a request's objects are taken and given on one thread. Objects that cross
threads: an idle server connection stolen by another worker (`WorkerPool::take(..., steal)`),
a `Buf` moved with it. The receiving thread's `give` puts it into its own cache; `allocated`
is a process-wide count and is untouched; the per-thread totals are each thread's own. A
`PoolBox<T>` is `Send` where `T: Send`; nothing else is needed. A shared tier would buy a
refill without malloc on one thread while another has spares; measure after S3 whether
`failures`/misses per thread ever justify it (expected: no, the floor covers it).

### 3.7 Arenas

`SessionArena`, the applet arena and `TaskArena` are index pools pre-sized to `maxconn`: their
slots are the "pool chunks" of HAProxy's `session`/`stream`/`stconn`/`task`. They keep their
own shape and gain three things from the shared machinery: (1) registration, so `show pools`
lists them with the same `PoolHead` the box pools use (`ArenaCounters` already exists: fold
it); (2) the floor semantics: the creation capacity is never given back (today's `floor`), and
burst capacity above it is released **only by `pool_gc`**, not by `trim_tail` on every drop
(Q2: keep the peak, as HAProxy); (3) a fallible grow on accept beyond `maxconn`'s pre-size
(`try_reserve`), refusing the connection on `Err`. T453's fix (`try_reserve_exact` for the
compaction copy, keep the old buffer on `Err`) is correct on its own and merges first; S4
moves the compaction under `pool_gc` and deletes the copy-on-drop.

### 3.8 One accounting path

Thread-local `count`/`bytes` per pool, `dirty` flag set by take and give; at the end of each
loop pass (`Engine::step`, where fix/t445's `poll()` already runs) the thread stores its dirty
pools' `(count, bytes)` into its slot of `shown[tid]` with `Relaxed` stores: cost per *pass*,
not per operation, and the line is written by one thread. `show pools` and `show info`
(`PoolAlloc_*`, `PoolUsed_*`, `PoolFailed`) read `allocated`, `failures` and the sum of the
per-thread snapshots; `used = allocated - cached`, exactly HAProxy's derivation (`pool_used`
reads the atomics that only the miss path moves; `cached_items` sums each thread's `ph->count`).
`needed_avg` is the swrate of `used` sampled on the miss path (`pool_alloc_nocache`): same
place, same cost (0 on a hit). Figures are at most one loop pass stale; HAProxy's per-thread
counts are read unsynchronised too. `show pools` names: HAProxy's where the object
corresponds (`buffer`, `trash`, `session`, `task`, `vars`, `caphdr`, `uniqueid`), Ibex names where
there is none (`spare_str`, `spare_list`, `logline`, `check_run`, `stats_row`); `users 1`, no
`[SHARED]` (Q5 (a)).

### 3.9 One wipe policy

`tune.ibex.zero-buffers on|off` (default on; Ibex extension) is the only switch. `reset(wipe)`
wipes the object's **used** length (buffers: `0..hwm` as today; strings: `len`; lists: each
string's `len`), never the capacity, with `zeroize` as `ibex_alloc::wipe` does now. The flag is
the thread's `Cell` copy (§3.2). Wipe cost is proportional to bytes handled, not to operations:
on the rules scenario today ~115 instructions per request for buffers; fix/t444's spare-string
wipe adds the strings' bytes (a few hundred bytes per request) and is kept.

### 3.10 Memory pressure, per case, against HAProxy

| Case | HAProxy 3.5-dev8 | Ibex after S5 (M1) | After S6 |
|---|---|---|---|
| Thread cache over `hot-size` | evicts oldest to `free()` (3/4, 7/8 rule) | same rule, largest-first across pools, floors respected | same |
| `tune.buffers.limit` reached / `malloc` fails for a buffer | emergency buffer, else the task **waits** on the per-thread buffer queue, woken by `offer_buffers`; the doc warns tasks "may freeze until their timeout expires" | `take` → `None`: GC once, retry; then **fail that stream** (`R`, 500 on HTTP), `failures += 1`, `buf_wait`-style counter | HAProxy's queue: pre-sized to maxconn (no allocation to wait), criticality classes, woken on `Buf` drop |
| Session/stream object cannot be allocated | refuse the connection (`session.c:397-420` static 500) or fail the stream (`stream.c:358`) | same, from the arena's fallible grow | same |
| `-m <MB>` | sets `RLIMIT_DATA`, computes `maxconn`; allocations fail with NULL under it and are handled | `maxconn` budget only (T453 §2); **set the rlimit only once S5 is merged**, with T446's `run.sh` as the test (HAProxy survived every run; Ibex aborted) | rlimit set |
| SIGQUIT / SIGTTOU / SIGUSR1 / stop | `pool_gc`: every pool down to `minavail`, `malloc_trim` | fix/t445: same triggers, registry walk, floors are `minavail` | same |
| Infallible allocation in a dependency fails | n/a (C checks NULL) | abort (`tradeoff.md` 6.23, `upstream/rust-recoverable-oom.md`) | unchanged until upstream |

## 4. Cost budget per operation

| Operation | HAProxy (measured on the binary's hit path) | Ibex budget | How the design meets it |
|---|---|---|---|
| take, cache hit | `__pool_alloc` 46 instructions (two `pool_debugging` tests, `tid` load, two list unlinks, three thread-local counter updates) | **≤ 50** | const-initialised `thread_local!` (`LocalKey::with` on a `const` TLS is a `%fs` load, no lazy-init branch), `RefCell::borrow_mut` (one flag check), `Vec::pop`, two `Cell` updates and `dirty = true` |
| give, cache hit, under 3/4 | `__pool_free` + `pool_put_to_cache` ~60 (two list inserts, three counter updates, one compare) | **≤ 60** excluding the wipe's byte loop | `reset(wipe)` call, `keep` compare, `Vec::push` within capacity, three `Cell` updates, one compare |
| accounting within the above | 3 thread-local adds + 1 compare ≈ 8 | **≤ 10**, zero shared cache lines | §3.8 |

## 7. Rules so this does not happen again (drafts; the user approves)

### 7a. Section for `review/agent-brief.md`

> **Memory: one pool, one budget, measured.** Every per-thread cache, spare list, free list,
> arena or "reuse" slot in Ibex is an `ibex_alloc::Pool`/`Arena` declared with `declare_pool!`
> (design: `docs/design/memory-2026-10-24.md`). Do not add a `thread_local!` holding a
> `RefCell<Vec<..>>`, `Cell<Option<..>>` or similar outside `ibex-alloc`; `harness/pool_layout.py`
> fails on it. A pooled object is counted, bounded by `tune.memory.hot-size`, wiped under
> `tune.ibex.zero-buffers`, drained by `pool_gc` and refused (not aborted) when memory is short
> *because* it is a `Pool`; a hand-written cache has none of that.
>
> The fast path (take, give) writes no shared memory: no atomic, no `Arc` store, no global
> load. Counters are thread-local and published once per loop pass. If you need a number another
> thread reads, put it in the pool's `publish`.
>
> Any change on the request path reports **instructions per request before and after**, from
> `tools/measure/insreq.sh` on `scenarios/keepalive.body` and `scenarios/rules.body` (min of 5
> rounds, `flock -x /tmp/ibex-load.lock`, pinned CPUs, governor `performance`), against the
> budget in the task: by default **+0.5%** over the base commit. A change that exceeds it does
> not merge, whatever else is green; write the number in the task's progress file and stop.
> No malloc on the request path (`request_allocations.rs`, `tools/allocprofile` at 0); if you
> remove one, say so; if you cannot avoid one, the parser refuses the feature (AGENTS.md §5).

### 7b. Rule for `AGENTS.md`

> ## 8. Memory has one owner
>
> A cache, pool, spare list or arena is an `ibex_alloc::Pool`/`Arena` (`docs/design/memory-2026-10-24.md`),
> or it does not exist. The fast path writes nothing another thread reads. A change on the
> request path ships with its instructions-per-request figure before and after
> (`tools/measure/insreq.sh`), inside the task's budget (+0.5% unless the task says otherwise).
> A number is a result; "should be cheaper" is not.
