# Design: HTTP/3 streams into the stream engine without the HTTP/1 relay (T498, 2026-10-26)

Status: design, no production code. Inputs: `m2-scope-2026-10-25.md` (§4.1, §5.4, slice 11),
`~/ibex-worktrees/review/quic-review-2026-10-25.md` (#3, #6), T492, T493, `memory-2026-10-24.md`.
Oracle: HAProxy 3.5-dev7 with QUIC (`~/reference/haproxy-quic`, `mux_quic.c`, `h3.c`,
`qpack-dec.c`), measured with an aioquic 1.3.0 probe (§8). Main at 7e9958ad.

## 0. Short answers

| Question | Answer |
|---|---|
| Decision | **Build the in-process path and remove the relay**, in five slices (§7), not conditional on slice 11's CPU figure. The relay's cost is not mainly CPU: it is **3 fds per in-flight request** where the `maxconn → RLIMIT_NOFILE` arithmetic assumes 2 per connection (`globalconn::maxsock`, `maxconn * 2`, `globalconn.rs:274`; an h3 burst hits EMFILE at a third of the `maxconn` the operator set), two kernel copies and an HTTP/1 parse per direction, trailers and 1xx dropped, a second stream object (`Relay`) and an unpooled `Vec` per request (T493 #2), and an h3 request that is a session of its own instead of a stream of its connection's (M2 §5.4). Each of these is a correctness or operations row, and each goes away with the same change. |
| Shape | An h3 request stream enters the engine **exactly as an h2 stream does**: the QUIC connection is the *owner* session entry of its worker (`TcpSession` with `h3_ctx: H3MuxContext`, `ClientSide::Quic`), each request stream is a *child* entry made by `h2_child_of`'s generalisation, moved by an `h3_owner_pass` that is `h2_owner_pass` over a mux trait, and served by the unchanged `h2_bridge` functions (`dispatch_next`, `start_request`, `pump_request_body`, `forward_response`) made generic over `HtxMux`. HAProxy's `qcc`/`qcs` ↔ `h2c`/`h2s`: same split, same owner. |
| Who owns what | The worker that owns the `QuicListener` (SO_REUSEPORT socket, T210) owns the connection, its mux, its stream contexts and every child: nothing crosses threads (AGENTS.md §8). The listener keeps `ConnectionId → (owner session idx, TaskRef)` and wakes the owner; the owner drains quinn's stream data into the mux and writes the mux's frames back, in its pass. |
| Buffers | Per stream: one `Buf` of `tune.bufsize` for the decoded request HTX (HAProxy's `qcs->rx.app_buf`), the child's `req`/`rep` `Buf`s as any stream; per connection: the stream map and one tx `Buf`. All from `ibex_alloc` pools (`buffer`, new `qcs`, `qcc`). Datagram batch buffers stay pre-allocated per listener. Target: **0 allocations per h3 request** in steady state (the h2 path's `request_allocations.rs` pin, duplicated for h3). |
| Flow control | quinn-proto holds the client's bytes up to the stream window; the owner reads a stream only when its HTX buffer has room, so the client's window (not Ibex memory) holds the body back, and quinn credits MAX_STREAM_DATA/MAX_DATA as bytes are read. Windows set to HAProxy's (§2.3). Tx: `write_stream` partial writes keep the rest in the stream's tx buffer; `StreamWritable` wakes the owner; children take the connection's send budget round robin as `h2_owner_pass` does (`send_list`). |
| QPACK | Measured (§8): HAProxy advertises `QPACK_MAX_TABLE_CAPACITY 0`, `QPACK_BLOCKED_STREAMS 4096`, `MAX_FIELD_SECTION_SIZE 2^62-1`; its decoder has **no dynamic table** (every TODO in `qpack-dec.c:328-466`), fails a non-zero Required Insert Count with `QPACK_DECOMPRESSION_FAILED`, an encoder-stream insertion with `QPACK_ENCODER_STREAM_ERROR`, and emits no insertions. Ibex's static-only decoder (`qpack::decode_qpack_static`, capacity 0, blocked 0) is **the same design**, not a corner cut; it stays. One change: the encoder stream must be *decoded* (Set Dynamic Table Capacity 0 accepted, anything else `0x201`), today it is discarded unread (§3). |
| Trailers, 1xx, CONNECT | Request and response trailers: forwarded (measured, §8), through the bridge's existing trailer path (`H2ReqBody::trailer_bytes`, `drop_rsp_trailers`). 1xx: the h3 mux sends an interim HEADERS without FIN (`h3.c` `H3_SF_SENT_INTERIM`) — and the shared bridge drops interim responses today for **h2 as well** (`h2_bridge.rs:233`), so this is one fix for both; the oracle **crashed** on my 103 test over h3 (§8, oracle defect, test over h2 until a fixed oracle exists). CONNECT: HAProxy resets the stream `H3_REQUEST_REJECTED 0x10b`; extended CONNECT (`:protocol`): `H3_MESSAGE_ERROR 0x10e` (no `SETTINGS_ENABLE_CONNECT_PROTOCOL`). Ibex does the same, by the mux, before any session exists. |
| Timers, counters, stop | Owner timer = the h2 owner's rule (`proxy.rs:1565-1575`): a stream with a partial head → `timeout http-request` from that stream's start (closes RV-16), idle → `timeout http-keep-alive`, fallback `timeout client`; quinn's 30 s idle (`tune.quic.fe.max-idle-timeout`) under it. Children: their own `timeout client`/`server` (T300). One frontend session per QUIC connection (M2 slice 2 is this design's slice H1, §7). Soft stop: owner sends GOAWAY (`next_request` id as today), closes when it has no child, nothing unacknowledged and the drain rule slice 6 measures. `answered` (T493 #2): gone — the stream map keyed by id with `dispatched`, entry freed with the stream (`recycle_stream`). |
| Budget | fds per in-flight request 3 → **1** (= HAProxy); allocations per request → **0**; instructions per h3 request ≤ **h2 keep-alive path + 15 %** (same bridge; the delta is QPACK vs HPACK and quinn vs TCP) and ≤ 1.5× HAProxy (M2 §3 row); RSS per idle h3 connection ≤ today + one `session` entry with unallocated `Buf`s (≤ 2× HAProxy, M2 row). Measured at night, slice H0 before and H4 after (§7). |

## 1. Today's path and what it costs

`quic_listener.rs::on_readable` reads a request stream into a `Vec` in `H3State.req`
(`HashMap<StreamId, Vec<u8>>`), `start_relay` decodes QPACK (static), re-serialises the head
as HTTP/1.1 (`h3_relay::request_head`, `Vec::with_capacity(256)`, `format!` per line), opens a
`socketpair`, pushes the engine's end as an `AcceptedStream`; `engine::adopt_quic_streams` →
`admit_connection(proxy, None, fd, …)` makes a **full session** for it (`sess.h3 = true`,
"no listener slot", `engine.rs:5907`, `7341`, `8728`). `advance_relays` then copies the body
to the socketpair and parses the HTTP/1 response back (`ResponseConv`) into HEADERS/DATA
frames in `outq`. Per request, counted in the code: 2 fds (socketpair) + the server leg;
≥ 8 syscalls beyond HAProxy's (socketpair, 2 sends, 2 recvs, 2 closes, the engine's own
poll registration); allocations: `chunk`, `held`, `first_headers().to_vec`, `rest.to_vec`,
`decode_qpack_static` (a `Vec<HeaderField>` and two `String`s per field), `headers_to_htx`,
`head`, `cookies`, `Relay { rx, to_engine }`, `ResponseConv`, `frames`, `out`, `OutQ.buf`,
`encode_field_section`, the session's spares — none pooled; `answered: Vec<StreamId>` never
pruned. Dropped: response trailers (`h3_relay.rs:414`), interim responses (`:362`). Counted
wrong: a stream is a session (`stot`, `scur`, `CurrConns`), the h3 bytes are the h1 bytes.

The h2 path for comparison (`mux_h2.rs`, `h2_bridge.rs`, `engine.rs:5630-5690`,
`8158-8230`, `9701-9735`): the connection's session owns `H2MuxContext`; `dispatch_next` takes
the lowest stream with its head in `rx_htx`; `h2_child_of` makes the child from the owner
(timeouts, TLS info, vars, spares, T437 memory); `h2_owner_pass` moves bytes both ways per
child and wakes it; `h2_child_released` gives back what the child changed. No fd, no copy
through the kernel, no second parse: the head goes to the child's `req` as HTTP/1.1 text
once (`start_request`, the engine's one HTTP/1 parser), which is what HAProxy's `h2s` →
`stream` does with HTX directly. The h3 design reuses all of it.

## 2. The stream object and its owner

### 2.1 Types (ibex-proto `mux_h3.rs`, grown from today's 240 lines)

```rust
pub struct H3StreamCtx {            // HAProxy's qcs; from Pool "qcs"
    pub id: u64,
    pub state: H3StreamState,       // Open, HalfClosedRemote (FIN read), Closed, Reset(code)
    pub rx: Buf,                    // raw H3 bytes not yet framed: ≤ bufsize-4 + 16 (today's cap)
    pub rx_htx: Htx,                // decoded request: ReqLine, Header*, Eoh, Data*, Trailer*, Eom
    pub rx_buffered: usize,         // DATA bytes in rx_htx the child has not taken (rx_taken)
    pub dispatched: bool,           // a child serves it
    pub tx: Buf,                    // frames not yet accepted by quinn (partial write_stream)
    pub tx_fin: bool,               // the response's last frame is in tx
    pub head_start: Tick,           // qcs->start: the http-request timer base while the head is partial
    pub interim_sent: bool,         // H3_SF_SENT_INTERIM
}
pub struct H3MuxContext {           // HAProxy's qcc + h3c; from Pool "qcc"
    pub streams: StreamMap<H3StreamCtx>,   // mux_h2's StreamMap made generic over the ctx
    pub control_out: Option<StreamId>, pub control_in / qpack_enc_in / qpack_dec_in: Option<StreamId>,
    pub settings_sent, settings_recv: bool,
    pub goaway_sent: Option<u64>, pub goaway_recv: Option<u64>,
    pub next_request: u64,          // GOAWAY id (today's H3State.next_request)
    pub max_concurrent: u32,        // tune.quic.fe.stream.max-concurrent (100)
    pub glitch_count: u32,          // qcc_report_glitch
    pub last_client_stream_id, head_partial: bool,  // the owner's timer rule reads these
}
```

`H3State`, `Relay`, `AcceptedStream`, `OutQ`, `answered`, `unacked` in `quic_listener.rs`
are deleted; the listener keeps transport only: sockets, endpoint, `peers`, soft-stop
pinning, and `owners: HashMap<ConnectionId, (u32 /*session idx*/, TaskRef)>`.

### 2.2 The owner entry

At `HandshakeComplete { alpn: h3 }` the listener calls `engine.admit_quic_connection(proxy,
listener_idx, conn_id, peer, local)`: the counters and `tcp-request connection` rules of
`admit_connection` with `l_idx = Listener::Quic(idx)` (global `maxconn`, the QUIC listener's
own `maxconn` counter and `scur`, `CurrConns`, `CumConns`, `CurrSslConns`/`CumSslConns`
— HAProxy's `quic_accept_push_qc` → `listener_accept` → `session_new`), then a `SessionEntry`
whose `TcpSession` has `cli: ClientSide::Quic { listener, conn_id }`, `h3_ctx:
Some(PoolBox<H3MuxContext>)`, `cli_raw_fd` = the UDP socket (for `show sess`, never polled
through this entry — as an h2 child's today), `cli_xprt` carrying the TLS info quinn
reports (ALPN, SNI, cipher, for `ssl_fc_*`). Frontend `maxconn` reached: the listener stops
accepting (`stop_accepting`) and refuses `Incoming` as HAProxy's listener does; measured in
slice H1 (M2 §5.4: HAProxy holds `scur` at 2 and the others wait).

Owner pass (`h3_owner_pass`, called where `h2_owner_pass` is, `engine.rs:9949`):

1. **Transport → mux.** For each `StreamOpened`/`StreamReadable` the listener queued for
   this connection: if the stream's `rx` has room (its `rx_htx` not full), `read_stream` into
   `rx`, then `mux.demux(stream)`: HEADERS → `headers_to_htx` into `rx_htx` (one HEADERS
   frame ≤ `bufsize - 4` or `H3_EXCESSIVE_LOAD`, as today), DATA → `HtxBlock::Data` appended
   while `htx_free_data_space` allows (HAProxy `h3_data_to_htx`), a second HEADERS after DATA
   → trailers, FIN → `Eom`. Unidirectional streams: control (SETTINGS once, GOAWAY,
   unknown frames skipped), QPACK encoder (decoded, §3), QPACK decoder (acks skipped),
   unknown type → `STOP_SENDING H3_STREAM_CREATION_ERROR` as `h3.c:285`.
2. **Children.** `h2_bridge::dispatch_next`/`start_request` generalised (§2.4) make a child
   per stream with `Eoh` in `rx_htx`, up to `max_concurrent`; `pump_request_body` moves DATA
   and trailers into the child's `req`, `forward_response` frames the child's `rep` into the
   stream's `tx`; `h2_bridge_state`'s equivalent tells the child about a reset
   (`StreamReset`/`StreamStopped`), the connection closing, or the owner's timeout.
3. **Mux → transport.** `write_stream` per stream with `tx` bytes, round robin from
   `next_child`; a partial write keeps the remainder (`StreamWritable` wakes the owner);
   `finish_stream` when `tx_fin` and `tx` is empty; `reset_stream` for a child that ended
   with an error (`H3_REQUEST_CANCELLED`/`H3_INTERNAL_ERROR` as HAProxy's `qcc_reset_stream`).
   Then `send_batch` runs as today in the engine's step.

Waking: the listener's `pump` no longer serves streams; it dispatches events to
`owners[conn_id]`'s queue and pushes the task onto `wake_queue` (the h2 owner is woken by
its fd; the h3 owner by the listener). `ConnectionClosed` → the owner ends with `ending =
client closed`, its children see it through the state pass as h2 children do.

### 2.3 Flow control and back-pressure

- **Rx.** Per stream Ibex holds at most `rx` (one buffer of raw frames) + `rx_htx` (one
  `tune.bufsize` buffer) + the child's `req`; what the client has sent beyond that sits in
  quinn-proto's receive buffer up to the stream window, and the client stops at the window.
  The owner does not `read_stream` a stream whose `rx_htx` is full; `rx_taken` (the child
  consumed DATA) makes it readable again. quinn credits `MAX_STREAM_DATA`/`MAX_DATA` on read
  (HAProxy: `qcs_consume` → `qcc_consume_qcs`, half-window rule, `mux_quic.c:1395-1416`).
- **Windows = HAProxy's** (measured §8): `initial_max_data = 1 638 000` (100 streams ×
  `bufsize - 4`), `initial_max_stream_data_bidi_remote = 1 474 200` (90 %,
  `tune.quic.fe.stream-data-ratio`), `_uni = 16 380`, `max_streams_bidi 100`, `max_streams_uni
  3`, `max_idle_timeout 30 s`, `active_connection_id_limit 8`. Ibex today: `receive_window
  1 MiB`, `stream_receive_window 512 KiB`, bidi 100, idle 30 s (`config.rs:58-70`). Slice H1
  sets them from `tune.quic.fe.stream.max-concurrent × (bufsize - 4)` and the ratio, so
  M2 slice 7's knob reaches both the transport and the mux. Per-connection bound on client
  bytes Ibex may hold: 1.6 MB in quinn + 100 × 2 buffers — the same order as HAProxy's
  (`qcc` rxbufs + `app_buf`), documented in `tradeoff.md`.
- **Tx.** `forward_response` frames at most `data_budget(stream)` = min(quinn's stream send
  capacity, connection capacity, `RELAY_BACKLOG`-sized `tx`), so a slow client stalls its own
  stream only; a child with `rep` it cannot frame keeps it there (server read stops when
  `rep` is full, as h2). Priority: round robin, no `PRIORITY_UPDATE` (HAProxy ignores it too).
- **Many streams.** `max_concurrent` children per owner; a stream opened beyond it is
  rejected by quinn's `max_concurrent_bidi_streams` (transport error, as HAProxy's
  `STREAM_LIMIT_ERROR`), heads waiting for a child slot stay in `rx_htx` under the budget.

### 2.4 Generalising the bridge

`h2_bridge` takes `&mut H2MuxContext` and `H2ActiveStream`; the h3 version needs the same
seven operations. Introduce in ibex-proto:

```rust
pub trait HtxMux {
    type Stream: HtxStream;                       // rx_htx, state, dispatched, rx_buffered, reset reason
    fn streams(&mut self) -> &mut StreamMap<Self::Stream>;
    fn send_head(&mut self, id, head: &[u8], end_stream: bool) -> bool;   // h2: send_h1_head; h3: HEADERS via QPACK static encoder
    fn send_data(&mut self, id, data: &[u8], end_stream: bool) -> usize;
    fn send_trailers(&mut self, id, trailers: &[(..)], ) -> bool;
    fn send_interim(&mut self, id, head: &[u8]) -> bool;                 // 1xx: HEADERS without end_stream
    fn data_budget(&self, id) -> usize;
    fn rx_taken(&mut self, id, n: usize);
    fn reset(&mut self, id, code);  fn is_reset(&self, id) -> bool;
    fn tx_pending(&self) -> bool;  fn glitches(&self) -> u64;
}
```

`H2MuxContext` implements it with its existing methods (`send_h1_head`, `send_data`,
`data_budget`, `rx_taken`, `send_rst_stream`); `h2_bridge` becomes `mux_bridge<M: HtxMux>`
with `H2ActiveStream`/`H2ReqBody`/`H2Role`/`H2Child`/`H2Owner` renamed `Mux*` (type aliases
keep the h2 names for one slice). `h2_owner_pass`, `h2_bridge_moves`, `h2_bridge_state`,
`h2_child_released`, `h2_spawn` are parameterised by which ctx the owner has (`h2_ctx` or
`h3_ctx`: an `enum MuxCtx { H2(Box<H2MuxContext>), H3(PoolBox<H3MuxContext>) }` on the
session, one `match` at the top of each). The h2 tests pin the behaviour: nothing an
existing h2 test asserts changes, and `h2_per_request_work.rs`'s instruction pin holds ±0.

## 3. QPACK: what HAProxy does and what Ibex does

Measured on the oracle (§8): SETTINGS `0x1 = 0`, `0x7 = 4096`, `0x6 = 4611686018427387903`.
`qpack-dec.c`: capacity instruction with a non-zero value → `QPACK_ENCODER_STREAM_ERROR`
(`:155-170`), any other encoder instruction → the same (`:173-177`), Required Insert Count ≠ 0
→ `QPACK_DECOMPRESSION_FAILED` (`:302-308`), decoder-stream Insert Count Increment →
`QPACK_DECODER_STREAM_ERROR` (`:224`); "TODO adjust this when dynamic table support is
implemented" at every dynamic reference (`:328, 376, 429, 466`). HAProxy's encoder
(`qpack-enc.c`) writes static references and literals only. So in 3.5-dev7 QPACK **is**
static-table-only on both sides; the 4096 blocked streams is advertised but can never be
used; M2 §2 keeps dynamic QPACK out.

Ibex: `decode_qpack_static` (99-entry static table, literals, Huffman; field count cap 201;
`enc_ric != 0` → decompression failure as HAProxy) and `encode_field_section` (static
index for `:status` 103/200/304/404/503, literal otherwise). Keep. Changes in slice H2:
(a) decode the client's encoder stream: Set Dynamic Table Capacity 0 is a no-op, any
non-zero capacity or insertion closes the connection `0x201`; decoder-stream Section
Acknowledgements/Stream Cancellations are skipped, Insert Count Increment closes `0x202`
(the oracle did not close within 2.5 s on my capacity-5 probe — §8; the row is RFC 9204
§4.3.1 + `qpack-dec.c`, verified with the red team's harness before the test is written);
(b) SETTINGS stays `0x1 = 0, 0x7 = 0`; `0x6` is 65 536 today and stays (HAProxy's
"unlimited" is bounded by `EXCESSIVE_LOAD` at `bufsize - 4` in practice, Ibex's value is the
honest one); (c) a static encoder with the whole table indexed by (name, value) and by
name, so a response head costs one lookup per field, no `String`.

## 5. Timers, counters, soft stop, `answered`

- **Timers.** The owner's `cli_exp` follows `proxy.rs:1565-1575`: `head_partial` (a request
  stream with bytes in `rx` and no `Eoh`) → `timeout http-request` from `head_start` of the
  oldest such stream (`qcc->opening_list`, `qcc_refresh_timeout`), a connection that served a
  request and is idle → `timeout http-keep-alive` (fallback `http-request`), else `timeout
  client`; on expiry the owner closes the connection (`CONNECTION_CLOSE H3_NO_ERROR` after a
  GOAWAY, as `qcc_timeout_task` → `qcc_shutdown`; the exact frames measured in H3b with the
  harness). This closes **RV-16** (partial head only bounded by the 30 s transport idle).
  quinn's idle timeout stays the transport floor. Children arm their own `timeout client` at
  dispatch (`arm_client`, T300) and `timeout server`/`connect`/`queue` as any stream.
- **Counters** (M2 §4.2): the owner is the frontend session (`stot`, `conn_tot`, `scur`,
  `CurrConns`, `CumConns`, `CurrSslConns`/`CumSslConns` at the handshake; `bin`/`bout` from
  the datagram bytes the listener attributes to the connection, as HAProxy counts
  `qc->bytes`); children count `req_tot`, `hrsp_*`, `%U`/`%B` per request; `maxconn` on the
  QUIC listener's counter. `sess.h3` and the "no listener slot" branches
  (`engine.rs:5907, 7341, 8728, 9315`) go away.
- **Soft stop / reload** (M2 slice 6): `begin_soft_stop` → each owner gets `stopping`, sends
  GOAWAY(`next_request`), refuses to dispatch streams ≥ it (reset `H3_REQUEST_REJECTED`, so
  the client retries on a new connection — what `ERR_DRAINING` in §5.3 was missing), and
  closes once it has no child and quinn reports every FIN acknowledged (today's `unacked`
  becomes "the stream is `Closed` and `finish_stream` acked", from quinn's stream events).
  The listener's pinned sockets and `-x` handover are untouched.
- **`answered` (T493 #2)**: no longer exists; the `StreamMap` entry is freed when the child
  ends (`recycle_stream` to the `qcs` pool), so a 10k-request connection holds `≤
  max_concurrent` entries. T493 #1 and #3 are transport-side and unchanged by this design.

## 6. Memory (memory-2026-10-24.md)

| Object | Today | Design |
|---|---|---|
| Request bytes per stream | `HashMap<StreamId, Vec<u8>>` growing per read | `H3StreamCtx.rx: Buf` from `buffer` (one, capped as today) |
| Decoded request | HTTP/1 `Vec` → socketpair → engine `req` `Buf` | `rx_htx` in a `Buf`; the child's `req` written once by `start_request` |
| Response | engine `rep` → socketpair → `ResponseConv` `Vec`s → `OutQ.buf` | `rep` `Buf` → `tx: Buf` (one per stream, pooled) |
| Stream / connection ctx | `Relay` (`Vec`s), `H3State` (`HashMap`s, `Vec`s) | `Pool<H3StreamCtx>` "qcs", `Pool<H3MuxContext>` "qcc", `declare_pool!`, in `show pools`, drained by `pool_gc` |
| Session | one `SessionEntry` + socketpair per request | one owner entry per connection, one child per in-flight stream (as h2) |
| Datagram buffers | `vec![vec![0u8; 2048]; 32]` ×3 per listener (`quic_listener.rs:207-209`) | unchanged (per listener, not per request); `prealloc`'d as the others when `pool_layout.py` lists them |

A `request_allocations_h3.rs` pin (counting allocator, one keep-alive h3 request after
warm-up: **0**) ships with H3a; `show pools` lists `qcs`/`qcc` with `users 1`.
